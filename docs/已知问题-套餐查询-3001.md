# 已知问题：套餐查询「获取失败」（上游接口返回 3001）

> 记录时间：2026-09-26 · 影响版本：3.14.x 全部 · 结论：**上游服务端行为，非本包问题**，不要在本仓库打补丁

## 现象

- 模型设置里 **Start Plan / 体验套餐** 一栏显示「获取失败 / 查询失败」，或显示「登录后查看」；
- 应用日志反复出现（实测累计 250 次）：

```
[coding-plan-availability] billing/balance 请求失败 {
  error: 'parameter error',
  providerId: 'account:bigmodel-start-plan',
  status: 400,
  url: 'https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=3.14.3'
}
[rpc:call] usage-stats.getEntitlementSnapshot FAIL (115.6ms) ApiError: parameter error
```

## 定位结论

**账号本身没问题**，是上游接口对"没有 start-plan 权益的账号"返回了笼统的参数错误：

1. 凭据完好：`credentials.json` 可用 `sha256('zcode-credential-fallback:linux:<数据目录>:<应用用户>')` 正常解密（AES-256-GCM 全通过），`oauth.restoreCachedSessionState OK`、`oauth.getActiveProvider OK`；
2. 网络与鉴权链路正常：同时间段 `coding-plan-subscription.getEnterprisePricing OK`；
3. 请求本身极简：`GET`，只带 `Authorization`（bigmodel 家族用 `zcodejwttoken`）与 `app_version` 一个查询参数；
4. **服务端对任意输入都回同一个 400**：

| 变体 | 结果 |
| --- | --- |
| 不带任何 query 参数 | `400 {"code":3001,"msg":"parameter error"}` |
| `?app_version=3.14.3`（与应用一致） | 同上 |
| `provider_id=start-plan` / `individual` / `providerId=…` / `account_id=…` | 全部同上 |
| `POST` | `404 page not found`（Go 路由只认 GET） |
| 换 `oauth access_token` 或 coding-plan 账号 api-key | `401`（该端点不接受这两种） |

5. JWT 载荷只有 `user_id / token_version / sub(账号) / iat`，**无 exp、无 plan/provider 绑定** —— 即服务端只能按账号解析权益，而这个账号持有的是 `bigmodel-individual-coding-plan`，没有 start-plan 权益。

## 上游应改的地方

- **服务端**：对无 start-plan 权益的账号返回 `code: 0` + 空 `plans`（客户端 `resolveStartPlanBalanceAvailability` 会映射为 `coding_plan_not_entitled`，正常显示"未开通"），或返回专用的"无此权益"错误码；**不要复用 3001（参数错误）**。
- **客户端健壮性**：`readApiJson` 侧把 3001 映射为 `coding_plan_not_entitled`，而不是硬失败并反复重试。

## 本仓库的处理

- **不改**打包产物：摘掉内置 `account:bigmodel-start-plan` provider 会让真正持有体验套餐的用户找不到入口；patch 压缩后的 `entry-http.js` 则每版都要重打，风险大于收益。
- 用户侧可忽略该卡片；编码套餐的额度查询走的是另一条链路（bigmodel 侧），与之无关。

## 复现脚本（只读，不打印令牌）

```bash
/var/apps/nodejs_v22/target/bin/node - <<'EOF'
const crypto=require('crypto'), fs=require('fs');
const file='/vol1/@appdata/zcode/data/.zcode/v2/credentials.json';   // 实际数据目录按设备调整
const data=JSON.parse(fs.readFileSync(file,'utf8'));
const secret='zcode-credential-fallback:linux:/vol1/@appdata/zcode:zcode';
const key=()=>crypto.createHash('sha256').update(secret).digest();
function dec(v){
  if(!v) return null;
  if(!v.startsWith('enc:v1:')) return v;
  const [iv,tag,ct]=v.slice(7).split('.').map(p=>Buffer.from(p,'base64url'));
  const d=crypto.createDecipheriv('aes-256-gcm', key(), iv); d.setAuthTag(tag);
  return Buffer.concat([d.update(ct), d.final()]).toString('utf8');
}
(async()=>{
  const r=await fetch('https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=3.14.3',
    { headers:{ Authorization:`Bearer ${dec(data['zcodejwttoken'])}` } });
  console.log(r.status, await r.text());
})();
EOF
```

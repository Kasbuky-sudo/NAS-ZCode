# 【原生应用】ZCode · NAS 版 v3.14.2 —— 把 AI 编程工作台放上 NAS，关掉浏览器它接着干

> 关键词：原生 fpk、不用 Docker、x86 + arm64 通吃、服务端权威、内置终端、访问令牌

## 这是什么

[ZCode](https://github.com/zai-org/ZCode) 是 Z.ai 开源的 AI 编程工作台：一个能看代码、改文件、跑命令的 agent，平时以桌面应用和终端形式使用。这个包把它**完整搬到 NAS 上**。

不是"把桌面软件塞进 NAS"——那需要虚拟显示 + 远程桌面，又慢又重。这里用的是官方自带的 Web 运行时（`zcode --web`）：**工作台只在 NAS 上跑一份**，你的电脑、平板、手机打开飞牛桌面点一下图标，看到的是同一个工作区、同一份登录态。

于是有了一件本地版做不到的事：**关掉浏览器，它照样在跑**。长任务、批量重构、跑测试这些活儿丢给它，你该干嘛干嘛，回来接着看结果就行。

## 主要特性

### 1. 服务端权威：关掉浏览器，它继续干

agent 与服务都跑在 NAS 上，前端只是个视图。跑长任务（批量改文件、装依赖、跑测试）时可以直接合上电脑，回来任务还在原地。这是本地版给不了的——关掉就没了。

### 2. 内置终端，浏览器里就是一台完整 shell

终端走服务端的伪终端（node-pty），在浏览器/飞牛桌面里直接可用，和桌面版体验一致。你可以在同一个界面里让 agent 改代码、自己再敲两条命令验证。

### 3. NAS 当工作区，多设备共用一份

登录态与配置保存在应用数据目录（升级、重装都不丢）；默认工作区是安装时创建的共享目录 **`zcode/workspace`**，在文件管理器里就能看到。手机看进度、电脑改代码，是同一个工作区。

需要让它操作已有目录时：应用中心 → ZCode → 应用设置 → 访问权限里加上该目录（系统会把 ACL 授予应用用户），之后在对话里直接给它路径即可。

### 4. 与桌面版同一套界面

Web 端和桌面版共用同一套前端组件：对话、任务编排、代码差异视图、内置终端都在。缺的只是桌面外壳那部分（系统托盘、原生菜单、自动更新）。

### 5. 有访问令牌把门，局域网里的其他设备用不了

ZCode Web 等于把一个能执行命令的 agent 和终端开在端口上，所以本包**强制带访问令牌**：

- 安装时向导要求填一个令牌（8–64 位字母数字，随便一串随机字符）；
- 桌面图标**自动携带**令牌，平时不需要手输；
- 服务端只对带令牌的请求放行，**同一局域网里其他设备没有令牌打不开**；
- 换令牌：应用设置里改，重启应用生效（换完不用手动清浏览器缓存）。

⚠️ **请勿把 8988 端口映射到公网**（别做端口转发 / 公网反代），建议只在局域网用；令牌也别设成弱口令或与 NAS 登录密码相同的值。

### 6. 为 NAS 场景做过的适配

- **桌面页内直接打开**：点飞牛桌面的「ZCode」图标，工作台嵌在窗口里，不跳新标签页。
- **依赖自动装**：manifest 声明了 `install_dep_apps=nodejs_v22`，安装时自动把应用中心的 Node.js v22 作为前置依赖装上，不需要你自己找运行时。
- **应用装在哪个卷都能跑**：Node 运行时按 `/var/apps` 统一视图跨卷解析，不写死 `/vol1`。
- **关得干净**：服务是三个进程（启动器 / 服务端 / agent），停止时按应用目录整组回收，不残留占端口的孤儿进程；重启 NAS 也会自动拉起。

## 安装

### 方式一：添加应用源（推荐）

应用中心 → 外部源 → 添加：

```
https://github.com/Kasbuky-sudo/FnDepot
```

以后有新版本会在应用中心里**直接提示更新**，不用再来翻帖子。这个源里还有其他应用（旅行青蛙、网易云音乐、Telegram、米游签、Compare Share），一并可见。

### 方式二：手动安装 fpk

1. 下载：`https://github.com/Kasbuky-sudo/NAS-ZCode/releases/download/v3.14.2/zcode-3.14.2.fpk`
2. 应用中心 → 手动安装 → 选中该文件

> **包为什么有 75.7 MB**：里面是完整的官方 Web 运行时（前端 + 服务端 + agent + 依赖），还包括 node-pty、koffi 这类**官方预编译的原生模块——而且是 x86_64 与 arm64 各带一份**，所以一个包就能双架构通吃。第一次安装传包慢一点是正常的，装完就好。

### 装好后

| 项目 | 值 |
|---|---|
| 端口 | `8988` |
| 桌面入口 | 飞牛桌面的「ZCode」图标，**页内打开**（iframe） |
| 访问地址 | `http://<NAS_IP>:8988`（面板入口会自动带上令牌） |
| 设置页 | 应用中心 → 已安装 → ZCode → 应用设置（改访问令牌、授权目录） |
| 数据目录 | `/vol1/@appdata/zcode/`（配置、登录态、日志） |
| 默认工作区 | 共享目录 `zcode/workspace`（文件管理器可见） |
| 架构 | `all`（x86_64 + arm64 一个包） |
| 运行时依赖 | 应用中心 Node.js v22（安装时自动装上） |
| 需要 Docker | 不需要 |

## 本次更新（v3.14.2）

这是 ZCode 的第一个飞牛版本，把上线前真机踩到的两个坑一并修掉了：

1. **修复点开图标后工作台连不上**（页面停在"Web 启动失败 / WebSocket connection failed"）。原因是服务端只放行静态页面、`/ws` 与接口要鉴权，而面板入口没带令牌；现在改成**令牌写进入口路径**，页面加载时自动完成鉴权，点开即用。
2. **修复重装或换过令牌后仍然连不上**。浏览器里会残留上一版安装的旧令牌，导致页面带着旧令牌握手；现在入口脚本会**用当前令牌覆盖旧 cookie**，升级不用手动清缓存。
3. 顺手把包体从 154 MB 压到 75.7 MB（初版打包重复带了两份应用内容）。

## 已知问题（如实告知）

1. **arm64 机型尚未完成本机验收**：x86 机型已实测通过（安装 / 启动 / 面板入口 / 鉴权全流程）；arm64 理论上同样支持（包内已带 arm64 原生模块），但我手上那台 arm 机器安装还没跑通，装完欢迎反馈结果。另外我在 CLI 侧遇到过安装任务卡在应用中心状态、报 `10500` 的情况，**从应用中心 UI 手动安装可绕过**。
2. **内置终端与各机型的原生模块 ABI 尚未逐一验证**：登录页、工作台界面、鉴权链路都已验证；终端（node-pty）是在登录后首次打开终端时才加载的，我还没有账号实测这一步。
3. **浏览器自动化（CUA）在 NAS 上不可用**：该能力依赖本机 Chromium，属于可接受的降级。
4. **上游迭代很快**：ZCode 还在 3.14.x 阶段持续更新，界面与行为可能随上游变化；升级前建议先备份工作区里的重要文件。
